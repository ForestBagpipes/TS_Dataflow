## 3. 方法诊断与改进方案

### 3.1 原型证据

四个脚本在本机运行，只读冻结的 v4.4 replay 产物，不调用任何模型：`scripts/proto_v46_selector_variants.py`、`..._variants2.py`、`..._variants3.py`、`..._variants4.py`，日志在 `artifacts/proto_v46_selector_variants*.log`。执行 agent 可以直接把这几个脚本移植到服务器复核。所有数字都是 TRAIN-eval 上的 source-macro MASE，与 v4.4 报告口径一致。

估计器形式的改动没有稳定收益。相对效用目标、1% winsor、按相关性或 ridge 系数加权的距离、ridge 先验加 kNN 残差的混合估计、按 horizon 或 source 切片、符号闸门，这些变体在 gate 选点后的 TRAIN-eval 结果都落在 Bolt 1.150 至 1.172、TimesFM 1.089 至 1.126 之间，事后最优配置的上限都在 Bolt 1.132 至 1.143、TimesFM 1.080 至 1.088。所有变体执行的干预里有 34% 至 45% 是有害的，这个条件有害率与动作本身的先验有害率（Bolt 0.40 至 0.47，TimesFM 0.37 至 0.42）相差不大，说明 bank 里能区分好坏干预的信号本身就弱。

bank 规模是主要杠杆。把 replay-fit 与 gate 合并为 184 个 parent 的 bank，再按 12.5%、25%、50%、100% 抽样，kNN 的 TRAIN-eval MASE 单调下降且在 100% 处仍未饱和（Bolt k = 32：1.160、1.148、1.137、1.131；TimesFM k = 32：1.094、1.088、1.084、1.077），而 ridge 与 CART 在 25% 后持平或回升（Bolt ridge 1.155、1.141、1.148、1.149）。这是全部原型里最重要的一条证据：非参数检索受益于更多历史，参数化预测器不受益。密化 bank 会拉开 Full 与 A5 的差距。

选参协议是第二杠杆。v4.4 在 48 个 parent 的 gate 上用两骨干联合 MASE 选出 (8, 1.64)，TRAIN-eval 上事后最优是 (8, 0)，差 0.033。改为在合并 bank 上做留一 parent 交叉验证，并以最佳固定非参考动作的条件有害率为 cap，Bolt 选出 (8, 0)，TimesFM 选出 (16, 0)，TRAIN-eval 结果与置信区间如下。

| Bolt | kNN (8, 0)，LOPO 选 | 1.1404 | 0.72 | 0.39 | −0.039 [−0.055, −0.025] | 相对固定 Multi TS-ICL −0.013 [−0.030, +0.003] |

对照的现状：A5 ridge 在合并 bank 上是 1.1486 / 1.0885，A5 CART 1.1484 / 1.0796；kNN 相对 A5 ridge 的配对差是 −0.008 [−0.023, +0.006] 与 −0.007 [−0.018, +0.004]，方向正确但不显著。密化 bank 后预期显著。

act-or-keep 的 KEEP 选项在当前 bank 上对 MASE 没有可测贡献：去掉 KEEP 选项的 always-act 在 Bolt 上是 1.129 至 1.132，与 act-or-keep 的差是 +0.003 [−0.004, +0.009]，TimesFM 上 +0.001 [−0.001, +0.003]。KEEP 是 oracle 最佳的 episode 占 17% 至 19%，能否识别它们决定这一层的价值，这同样依赖 bank 密度。写作上要按这个事实来写，见第 5 节。

β 的作用与骨干有关。Bolt 上 β 从 0 到 2.5，MASE 单调变差，干预率从 0.72 降到 0.05，条件有害率基本不变；TimesFM 上 β = 1.64 反而最好（1.0781，干预率 0.49，条件有害率 0.33）。所以 (k, β) 必须逐骨干选，不能像 v4.4 那样两骨干共用。

动作异质性的动机证据已经在手：TRAIN-eval 上 oracle 最佳动作的份额在 Bolt 是 KEEP 0.19、FFILL 0.26、Single 0.16、Multi 0.17、Ridge 0.22，在 TimesFM 是 0.17、0.23、0.18、0.19、0.23；Bolt 上没有任何固定动作平均优于 KEEP，TimesFM 上固定 Context Ridge 比 KEEP 好 0.139。最佳动作既随请求变也随骨干变，这两句可以直接进 §4.2。

### 3.2 方法改动清单（不改三层结构）

改动一，bank 密化。replay-fit 块内每个 704 行的 parent 增加起点：在 `read_start + 512 + j·s` 上取 origin，`s = 352` 时 j 取 0、1，`s = 176` 时 j 取 0 到 3，目标窗越过块边界的起点丢弃。每个 bank episode 另加两个 mask 种子（`PROTOCOL_SEED + 1`、`+ 2`），只用于 bank，评估侧仍用主种子。优先级是起点先于种子。`pipeline.EpisodeSpec` 已含 origin 字段，`mask_seed` 已含 protocol_seed 参数，改动集中在 `splits.episode_grid` 与 `masking.mixed_severity` 的调用，bank 记录的 cache identity 自动区分。预算见第 4.2 节。

改动二，选参协议。k 网格扩到 {8, 16, 32, 64}，β 网格 {0, 0.5, 1, 1.64}。选点在整个 replay-fit bank 上做留一 parent 交叉验证：一个 parent 的全部起点、种子、模式、horizon 的 episode 一起留出，对其余记录检索。目标是最小化 LOPO 的 source-macro MASE，约束是 LOPO 的条件有害率不超过 cap，cap 定义为 replay-fit 上平均效用最高的非参考动作在同一批 episode 上的条件有害率；无可行点时退回 β 最大的点。逐骨干独立选，Chronos-2 用同一冻结程序在自己的 bank 上选。cap 值、每个骨干选出的 (k, β)、LOPO 表全部写进 `results/v46/protocol/freeze_note.md`，并在读取任何 TEST 记录之前提交。原 gate 块并入 replay-fit，TRAIN-eval 块保留为冻结前的验收。

改动三，特征权重作为可选项。按相关性加权的距离在 Bolt 上有帮助（β = 1.64 时 1.1506 对 1.1658），TimesFM 上略差。不进入主方法，作为附录 E 的一行 `relevance-weighted distance` 报告。如果密化 bank 后它在两个骨干的 LOPO 上都更好，再提升为主方法，正文 §3.3 改为 `standardised Euclidean distance with per-feature weights fitted on replay-fit`。

改动四，消融重定义。A1 全局效用（不检索，取动作平均），A2 去掉干预状态，A3 去掉参考预测状态，A4 改为 always-act（去掉 KEEP 选项，执行得分最高的动作），A5 参数化 ridge。β 的敏感性从消融表移到附录的风险与干预率曲线（Figure 3b 的数据来源），k 的敏感性在附录 E 的 gate grid 表。Reconstruction Oracle 从 Table 4 移到附录 D。

改动五，不做的事。不加 support gate，不加 learned encoder，不改动作目录，不做输出集成。相对效用目标、winsor、混合估计都不采用，因为没有证据。

### 3.3 harm cap 的精确定义（供代码实现）

设 replay-fit 的 LOPO 预测已完成。对每个非参考动作 a，令 `m_a` 为它在 replay-fit 全部 episode 上的平均实际效用，`a_fix = argmax_a m_a`。cap 定义为 `c = mean_i [ g_{i, a_fix} < 0 ]`，即固定执行 `a_fix` 时的条件有害率（它在每个可用 episode 上都执行，所以条件率等于无条件率）。候选 (k, β) 的 LOPO 条件有害率是执行了干预的 episode 中 `g < 0` 的份额。可行集是条件有害率不超过 `c` 的候选，从中取 LOPO MASE 最小者。用本机数据算，Bolt 的 `a_fix` 是 Multi TS-ICL，`c = 0.47`；TimesFM 的 `a_fix` 是 Context Ridge，`c = 0.35`。这样定义的好处是正文可以写成一句话：the method may not be more harmful, conditional on intervening, than the best fixed intervention would be。

### 3.4 预期结果与写作上的对应

密化 bank 后的目标是 TRAIN-eval 上 Full 相对 A5、A1、A4 的配对差都不含零，相对 KEEP、Best Fixed、R2-CART 在两个骨干都显著。这是启动 TEST 的验收条件。如果密化后 Full 仍与 A5 不可区分，方法本身改为 ridge 先验加局部残差修正（原型 HYB 变体），§3.3 改写为 local utility estimation as a global linear prior corrected by same-action neighbours，A5 相应改为去掉局部修正。这个分支在 9/20 中午前决定。

## 4. 实验规划

原则沿用 `docs/IntroActTS_20260918_v46_experiment_plan.md` 的产物 DAG 与缓存原则：每个 unique input 每个骨干只预测一次，所有表和图从同一份 cache 派生。下面只写与 v46 规划不同或更具体的部分，未提到的按 v46 规划执行。

### 4.1 P0 冻结（9/19 上午，CPU 约 3 小时，GPU 15 分钟）

TEST 定义。TEST 取 `main_protocol_v2.json` 中 calibration 与 test 两段行区间的并集（每个来源的最后 25%），parent 以 704 为步长从区间起点铺满，context 不越过区间起点。按此 ETTh1/ETTh2/Traffic 各 6 个 parent，ETTm1/ETTm2 各 24，Electricity 9，Exchange 2，Weather 18，共 95 个 parent，10% 下 760 个 episode。只取 test 段则只有 54 个 parent 且 Exchange 只有 1 个，统计单位不够，所以建议合并。合并是在读取任何标签之前的协议决定，写入 freeze_note 并说明 calibration 段从未被任何方法读取过。TRAIN 取 train 与 dev 两段（284 个合法 parent），说明 dev 段曾用于已废弃方法的开发评估但从未参与本文方法与 TEST。TRAIN 内部按时间分 replay-fit 80% 与 TRAIN-eval 20%，purge 704。

产物：`results/v46/protocol/test_manifest.json`（每来源边界、parent、origin）、`train_partition.json`、`freeze_note.md`。验收：TEST 与 TRAIN 无重叠行，边界 purge 审计通过，`heldout_labels_read = 0`。

协议常量。`protocol.py` 新增 `K_GRID = (8, 16, 32, 64)`、`BETA_GRID = (0.0, 0.5, 1.0, 1.64)`、`BANK_ORIGIN_STRIDE`、`BANK_MASK_SEEDS`、`HARM_CAP_RULE = "best_fixed_conditional_hir"`、诊断计数规则四条、机会分层的两个分位数（在 replay-fit 上算一次）。所有常量落盘到 `results/v46/protocol/protocol_freeze.json`。

测试。`tests/v44` 的 27 项契约在新 grid 下必须仍然通过，新增 LOPO 不跨 parent、cap 计算、always-act 语义、密化后 cache identity 不冲突四项。

吞吐探针。用一个来源一个 horizon 的切片测 Bolt、TimesFM、Chronos-2 的 unique-input 吞吐和 TS-ICL 的插补吞吐，写 `results/v46/protocol/throughput_probe.json`。v4.4 的实测参考：TS-ICL 约 30 毫秒一行，Bolt 约 0.09 秒一个输入，TimesFM 约 0.2 秒一个输入，Chronos-2 未测。

### 4.2 P1 bank 密化与选参冻结（9/19 下午至 9/20 中午）

GPU 队列一，按顺序：Bolt 密化 bank 的 A 至 D 阶段，TimesFM 同上，Chronos-2 同上。密化倍数由探针决定。以 ×4（两个起点 × 两个种子）估算：约 227 个 parent × 4 × 8 ≈ 7300 个 episode，约 33000 个 unique input，Bolt 约 50 分钟，TimesFM 约 1.8 小时，Chronos-2 若与 TimesFM 同量级约 2 小时，TS-ICL 三次各 8 分钟。×8 时翻倍。总计 5 至 10 小时，可在 9/20 早上前完成。每完成一个骨干立即写 bank 与 summary。

CPU 并行：实现 LOPO 选参、cap、always-act、诊断计数、机会分层、bootstrap 与 Holm 的后处理模块，全部以 v4.4 的 catalog cache 接口为输入，在旧 bank 上先跑通并与本机原型对数（Bolt kNN (8, 0) 合并 bank 应得 1.1404）。

选参与验收（9/20 上午，CPU）：三个骨干各自 LOPO 选点，写 freeze_note；TRAIN-eval 上跑 Full、A1 至 A5、KEEP、Best Fixed、R2-CART、Catalog Oracle，配对 bootstrap。验收条件见第 3.4 节。通过后提交 `v46 configuration frozen` 的 commit，记录 SHA，此后不再改选择器代码。

### 5.2 要新写的英文段落

Best Fixed 与 R2-CART 的定义（§4.1）：
Best Fixed applies to every request the single catalog action with the highest mean realised utility on the replay bank, so it is the strongest policy that ignores the request. R2-CART fits one depth-three classification tree per action on the same state features, each predicting whether that action is the oracle-best one, and executes the most confident action when its probability exceeds one half.

选参与 cap（§3.4）：
k and β are selected once per backbone by leave-one-parent-out cross-validation on the replay bank. Among the grid points whose conditional harmful rate under cross-validation does not exceed that of the best fixed intervention, we take the point with the lowest cross-validated MASE, so the method may not be more harmful, conditional on intervening, than the strongest fixed intervention. The selected point and the cap are recorded before any TEST record is read.

Chronos-2 的迁移句（§4.1）：
Chronos-2 enters after the procedure is frozen. Its replay bank is built with Chronos-2 itself and its k and β are selected by the same cross-validation rule on that bank, so the held-out result tests the transfer of a frozen procedure to a backbone family that took no part in method design.

A4 的定义（§4.6）：
A4 removes the reference option and executes the highest-scoring action on every request, which isolates the value of being allowed to keep the input.
