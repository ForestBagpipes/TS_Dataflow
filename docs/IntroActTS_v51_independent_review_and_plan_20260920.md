# IntroActTS v51 独立审阅、对照与全文规划

日期：2026-09-20。对应论文 `latex/IntroActTS_20260920_v51.tex`。本文只是一份审阅与规划文档，不是论文替换稿，没有修改 LaTeX、参考文献、图表、实验代码或结果，也没有运行新实验。

## 1. 独立 ICLR 审稿判断

本节不调用 work2 审阅插件，不采用其八角色评分或投票流程，由当前助手直接依据全文、表格及少量只读溯源材料作出判断。由于与工具审查共用宿主和上下文，它是另一套判断框架下的独立论证，不是隔离盲审或第二个独立模型。以下判断以稿内数值为条件，不代表已经复现实验。

**当前建议为拒稿，主要障碍在证据可信度和贡献成立条件，语言质量不是决定性障碍。** 对文内冲突判断的信心较高，对实际实现是否正确及原始结果是否成立的信心受限。修复文字冲突是必要步骤，但不能独自使论文达到接收标准。

论文有一个清楚而有价值的问题。固定预测器面对缺失输入时，需要判断某次修复是否比原生处理更有用。历史完整动作反馈可以监督这一决策，KEEP 使不干预成为明确选项。稿件保留了简单强基线、负面消融和事后评估披露，这些是应继续保留的优点。

### 1.1 首要问题是读者能否相信证据链

正文的 post-hoc 声明诚实而必要，但它说明当前主表不足以承担独立确认的角色。已披露偏差不等于已消除偏差。即使逐 parent bootstrap 的计算完全正确，所得区间仍未涵盖反复选择方法、报告条件和叙述重点带来的不确定性。

此外，全文还有可直接定位的冲突。`app:transfer` 对误差随距离的总括与 TimesFM 的 0.559/0.205 不符。`app:seeds` 声称 H=96，却使用与主表双 horizon 汇总相同的 1.378；对应 H=96 分表为 Bolt 1.173 和 Chronos-2 1.111。成本附录缺少从测量日志到总延迟及计数的明确映射。这些不是格式问题，也不能由图形与 CSV 完全一致来证明无误。

我的要求会是提供可追踪的运行清单，说明哪些结果已经验证，哪些只有历史汇总，哪些需要重建。在此之前不把任何一组冲突数值默认为正确，也不据此推断存在数据造假。

### 1.2 为什么必须使用当前选择器尚未回答

方法由固定特征、同动作近邻回归和启发式惩罚组成。把这些组合用于输入修复有应用价值，但 ICLR 审稿人会进一步问，该组合揭示了什么此前简单算法选择方法无法得到的结果。

表2中的 A2 去掉 intervention state 后，MASE、RMSSE、条件伤害率、harmful loss 和调用数的报告值都优于 full。A5 线性预测器的 MASE 也与 full 接近。对 full 与 Best Fixed、CART 的准确率优势，现有区间不能提供充分支持。这些事实不证明方法无效，却削弱了把复杂状态检索作为核心技术贡献的论证。

没有必要先预设 full 必须获胜，再补实验解释它。更合理的路线是在未接触确认集的开发阶段决定最终结构。若较小状态或线性模型稳定更好，应据实采用更简单的实现，并重新判断论文的研究贡献是否足够。

### 1.3 伤害减少可能主要来自少干预

降低干预频率本身就会降低累计伤害。稿中 β 扫描显示覆盖率明显下降，条件伤害率变化较小。默认工作点的 harmful loss 较低，还不能证明分散度惩罚识别了危险修复。

关键缺少同干预率或同实际成本下的比较。应检验局部惩罚是否优于对相同候选动作进行随机保留、均值阈值选择或线性效用阈值选择。如果优势只在调用数较少时出现，论文应把结论限制为有用的操作点，而不是不确定性估计带来的可靠选择。

### 1.4 历史记录的相关性直接影响惩罚含义

一个 parent 产生多个 mask、horizon 和 severity，邻域中的记录不一定是独立证据。权重有效样本量只描述权重集中程度。作为数学直觉，重复存储同一批相同记录不会增加新信息，却会增加这一 n_eff 并减小当前惩罚。这说明它不能在没有其他条件时被解释为独立证据量。

当前稿已明确否认校准保证，因此不能把此项评成一个不存在的定理被推翻。真正需要回答的是，惩罚是否对 parent 重复、bank 大小和邻域构成稳定，且是否改善决策。无可行超参数时回退最大 β 也不自动保证达到伤害率 cap。

### 1.5 输入契约与实现语义需要先统一

输入未观测位置的 `X^a-X^0` 必须有明确含义。静态 `state.py` 中缺失差值归零的操作，在参考含 NaN 时可能使幅度特征退化。当前没有证据把检查到的工作区代码等同于生成整篇结果的确切版本，因此这是高优先级待核实风险，而非已确认的全部实验失效。

正文还需明确 frozen 是参数不更新，还是同时要求黑盒、无梯度、保留所有已观测值。这些是不同约束。按黑盒约束排除梯度型基线可以合理，但约束应在问题定义里先给出，不能只在排除基线时出现。TATO 的变换操作与观测值保留要求也需明确如何兼容，或标为更宽契约下的上下文比较。

### 1.6 效率结论应以真实部署成本为准

1.65 次预测骨干调用是清楚的计数，但选择前已经生成五种候选，其中包含修复模型调用。它不能直接说明系统便宜。现有成本日志分别记录检索和骨干时间，没有据此建立全文总延迟表的充分映射。

应比较获得相近预测误差需要多少实际时间，以及相同时间内能获得多大改善。离线建 bank、修复器训练、每请求候选生成、检索、额外预测及失败处理都应进入相应账目。cache 上的策略重放不是端到端在线测量。

### 1.7 泛化范围仍然窄于部署动机

三个严重度都出现在 bank 中，三种骨干分别建 bank，八个来源也用于 replay。现有结果回答的是已登记网格内的应用表现。新模型、新来源、新缺失机制和自然缺失是不同问题，不能由同一严重度曲线统一代表。

不必为了凑实验扩到所有问题。至少选择一种与论文实际部署承诺相符的未见条件，并明确其信息边界。若无法补充，应保留受控缺失、固定网格内的定位。

### 1.8 写作需要围绕决策命题组织

当前写作的主要缺陷不是词汇华丽，而是方法细节、审计口径和限制分散。一个简单决策主线被大量重复边界说明打断。应让读者依次理解需要作出的决策、部署时缺少的信息、历史数据能估计什么、规则如何执行，以及实验在哪些条件下支持它。

应保留测试复用、竞争基线和负面结果等决定性信息。压缩重复段落不能变成隐藏限制。也不建议为了增加理论感而加入不影响算法或可检验结论的定理。

## 4. 全文 LaTeX 规划

规划分两种状态。证据尚未补齐时，维持当前 exploratory/post-hoc 定位，只能作证据一致性和表达整理。独立确认完成后，依据真实结果形成下一版投稿稿。新稿可命名 `IntroActTS_实际日期_v52`，现在不创建该 tex 文件。

**建议主线：历史预测效用可以用于逐请求选择输入修复，KEEP 提供保留原预测的决策选项。论文要检验这一选择在准确率、修复伤害和实际成本之间是否产生可靠收益。** 这是待证的研究问题，不预设本方法已经全面解决。

### 4.2 引言的五段任务

第一段交代具体运行条件。预测模型固定，输入可能缺失，实际可控对象是合法修复。避免从 AI 或数据质量的重要性铺陈。

第二段交代决策困难。修复值更接近隐藏真值，不保证未来预测更准确。逐请求效用依赖未来，因此当下无法直接比较全部动作。这里引用必要文献，并预告受控诊断，不把相关工作逐篇排成列表。

第三段引出可用信息。历史已结算窗口可以提供同一预测器下各动作的实际效用。说明该监督如何与部署问题对应，也交代模型特定 bank 和已有标签的需求。

第四段简要说明处理流程。形成状态，估计各动作收益，满足规则时执行一个修复，否则 KEEP。只讲一条连贯流程，不在引言列满 22 个特征和超参数。

第五段给出经确认的研究发现和范围。主效果、伤害或成本中的哪一项获支持就陈述哪一项。简单模型更优、不显著比较和 post-hoc 状态不能用修辞隐藏。贡献不一定要列三条，最多保留两项真正独立的贡献。

### 4.3 方法正文的四个单元

1. **Historical utility supervision**：动作可用性、训练窗口及效用差，说明完整动作反馈，不包装成在线探索。正文只保留一次效用公式。
2. **Observable state and estimation**：先定义参考缺失输入的表示和修复幅度基准，再讲状态与检索。完整特征表移附录，但正文必须可理解各输入的含义。最终采用何种状态由开发阶段证据决定。
3. **Act-or-keep selection**：展示经验分数和执行分支，明确 β 的作用、调参区域、parent 分组、不可用动作及回退。不给该分数添加未经建立的安全解释。
4. **Execution and accounting**：用一个简洁算法框交代离线和在线顺序。明确修复候选在选择前已构建，分开预测骨干次数和端到端时间。

如果最终选择器改成小状态或线性模型，该节据实重写，不能为了维持复杂架构图强行保留无用模块。此变化将需要新版本和独立确认，不属于本轮动作。

### 4.4 实验正文的四个问题

**问题一：选择策略是否改善预测？** 先给主实验表，比较 KEEP、固定修复、简单效用选择器、最终方法和明确适配的 TATO。按 backbone 展示配对效应与区间，避免只突出总体均值或 rank。

**问题二：是否作出了更好的修复决策？** 同一组合图展示相同干预率下的 MASE 与 harmful loss。条件 HIR 作为补充维度，KEEP 的条件量保持未定义。oracle 仅作可达空间诊断。

**问题三：哪些组件必要？** 只用消融表。预先选定状态、估计器、惩罚及 KEEP 的有限对照，不堆叠所有可能组合。正文解释正负结果，不只复述数字。

**问题四：边界和成本在哪里？** 未见机制或严重度实验各自用一张组合图，成本实验用一个高密度组合图。两个实验可横向并排排版并在图题中区分，但不能把互不相同的统计口径画在同一坐标轴上。

如果九页装不下，优先保留 matched-coverage 和真实成本，已在 replay 中出现的三点严重度曲线可移附录。所有进入正文的非主实验、非消融实验均有图片。图1和图2继续保留用户当前资产，本轮不改。

### 4.5 图表与附录组织

主表与消融表固定保留。实验图使用 Python 直接从经确认的表格数据生成 EPS，一实验一个组合图。各图统一冷色、同方法颜色、打印字号、图例位置、面板高度、竖柱及数值格式，不画背景网格。不同量纲允许不同刻度步长，同类量纲的轴范围尽量一致，不为表面一致牺牲可读性。

附录建议重组为 A 协议与数据，B 完整方法与输入契约，C 完整结果和配对不确定性，D 机制与消融，E 泛化边界，F 成本失败与运行身份，G 复现与开发历史。旧探索结果明确分区保留。所有底表跟随对应图的证据节，导航同步覆盖新增节。

## 5. 实验规划

以下是当前助手在用户授权下独立提出的未来规划，不是插件批准的执行协议，不表示已运行或必然得到正结果。实验、统计重算和实现验证仍只能在指定服务器环境执行。本轮没有使用未经授权的外部模型 API。

### E0 先解决身份和一致性，优先级最高

逐表登记 source/config/code/checkpoint/split/mask/统计口径。特别追踪 H=96 稳定性表、效用表的骨干与聚合范围、latency 总表、三骨干计数，以及 intervention features 的缺失值语义。只做必要的静态追踪后，由服务器进行有边界的重建验证。旧结果不能静默覆盖，错误、失败与无法追溯项均保留。

验收条件是每个主张都能定位唯一运行来源，修复后的实现与所述方法一致。v47_verified 文件存在或单元测试通过不等于方法晋升。若语义修复改变预测或选择，必须产生新运行标识，不能沿用旧稿结论。

### E1 冻结开发与独立确认

现有 TEST 继续作为已接触的开发证据，保留原名与历史说明，不能改名后当作新确认集。另选从未用于方法选择和结果检查的时间段或来源，按时间与 parent 排除重叠，隔离窗口上下文和未来。新集若已被其他任务查看，也不再满足独立要求。

模型、特征、候选目录、k/β 搜索、baseline、主要比较、聚合、失败处理和报告规则必须先冻结。未通过数据和 worker 语义检查前不进入效果实验。开发试验按项目现有契约从 32 个 train/dev origin 的 pilot 开始，只用开发侧估计资源和精度需求，不读取确认标签。

样本量不能现在拍一个数字。用开发侧 parent 配对差和来源差异估计期望区间宽度与最小有意义效应，再根据资源决定每来源父窗口数。mask 变体和模型重复不算新增独立 parent。确认集只按冻结方案评估，结果不理想时如实报告，不能继续以其调参。

### E2 主比较与公平基线

保留 KEEP、训练侧 Best Fixed、Fixed SAITS、CART 和当前方法。增补或强化三个最直接控制：线性效用选择器、训练侧按 source/horizon 固定选择的简单策略、线性插值后直接预测。它们都回答比继续堆新大模型更直接的疑问。可在资源允许时用一个非线性效用回归器作附加检查，但不无限扩展搜索。

TATO 保留为近期域级适配对照，补清楚官方版本、适配改变、观测保留契约、训练窗口量和搜索成本。必须把 identity+插值单独列出，区分修复与变换的作用。官方方法和预算受限适配如有不同，分别命名。各方法可见监督和调参预算必须登记，不能仅写同一 TRAIN 就宣称相等。

主结局为冻结的 source-macro MASE，辅助为 RMSSE、harmful loss、干预率及真实成本。来源内部按 parent 配对，各来源等权。统计过程按来源分层重采样 parent，并共同保留同一 parent 的相关变体。只有八来源时，不把结果写成任意新领域的总体推断。

对预先指定的主要方法比较报告配对差、区间与多重比较处理。区间包含零不写成两方法等效，等效或非劣结论需另行预先定义有意义的界限。

### E3 决策质量与干预频率分离

固定动作评分器和候选生成过程，在开发集选择一组预登记阈值，形成覆盖率范围。比较 dispersion penalty、仅均值阈值、线性效用阈值，以及独立随机门控。随机门控在固定的候选推荐后决定是否 KEEP，使动作选择与少干预两种效应可分辨。

阈值和随机门控概率从开发集固定，确认集报告实际覆盖率，不能利用确认集收益挑最优阈值。若另做使用确认分数分位数匹配覆盖率的图，只能标为离线诊断，不能冒充冻结部署策略。

同一图展示 MASE 随实际干预率和 harmful loss 随实际干预率的变化，并给主要预定点的 parent 配对区间。若惩罚不优于匹配门控，结论应转为操作点选择，不能继续主张更准确的不确定性识别。

### E4 状态与检索机制

在开发集比较 full、去 intervention state、去 reference forecast state，以及局部与线性效用估计。只保留针对关键假设的有限交互，必要时比较按独立 parent 聚合的邻域和现有按记录邻域。跟踪特征有效维度、非有限值、各 parent 的总权重和动作支持。

最终结构在独立确认之前决定。确认阶段固定结构，消融只检验预定机制，不再决定下一版赢家。指标优先最终决策 MASE、harmful loss、regret to catalog oracle 和实际时间，距离误差相关只作为辅助。

若去特征持续更好，就简化。若线性与局部方法在相同覆盖率下没有可靠区别，必须重新评估检索是否值得成为论文标题级贡献。

### E5 泛化边界

必需的最低方案是只选择一个与主张直接对应的留出轴，例如未在 replay 中出现的缺失机制，或未见严重度。选择哪个轴应在开发阶段固定。训练 bank 不得含该条件，再在确认 parent 上统一评估所有策略。新来源测试必须说明是否重新训练 imputer 或重建 bank，这两种设置回答不同问题。

自然缺失作为重要强化实验。未来预测标签可观测时可以评估预测误差，即使自然缺口真实值不可知也不能伪造重构误差。必须保留真实时间位置、目标与辅助通道可见边界以及故障记录。若获取不到可信自然数据，不虚构部署验证。

### E6 端到端成本

在固定硬件、batch、精度、模型驻留和 warm-up 规则下测请求时间，包括候选修复模型、参考预测、检索与被选动作预测。cache 策略分析和真实在线运行分表。分别给均值、P95、失败率、候选构建组成、离线构建和冷启动。

对照必须运行相同服务边界。A2 若希望节省候选生成，须实现确实无需候选的执行路径后再测，不能从删特征或读取同一 cache 推断速度收益。即使不干预仍支付的成本明确计入。

结果用一张组合图表达实际时间与预测质量，以及组件时间的竖向堆叠柱。离线费用按版本单独报告，只有声明明确请求量后才讨论摊销。

### 实施顺序与停止规则

E0 → 开发侧语义检查与 pilot → E2/E3/E4 开发比较 → 冻结最终方法及确认方案 → E1 确认评估，同时完成预定 E5/E6。

若 E0 不能确认来源，停止把相关数字作为主结果。若开发比较没有比简单选择器更好的准确率、伤害或成本关系，停止增加模块，考虑收缩方法或改成有价值的系统性经验研究。没有独立确认时不能仅凭语言规划把当前论文提升成已验证方法论文。上述判断不设定“必须达到显著”后才停止的可选停止规则。

## 6. 交付与下一版前置条件

本轮交付工具意见草稿、独立审阅、对照、参照论文分析及全文/实验规划。没有提供可直接覆盖正文的英文段落，没有改图，也没有新建论文版本。

下一版应从四个事实问题开始：当前稿各关键表的唯一运行身份，输入差值特征实际如何处理 NaN，成本数据测量边界，以及是否存在真正未接触的确认数据。它们决定后续是修正文稿、修复实现并重跑，还是需要调整研究贡献。最终语言和结构应服从这些答案。
