# 反向提纲（logic outline）— 修订后目标结构

每段一句中文中心句。通读检查：场景→方法→实验→结论是否连续。
本提纲先于英文重写定稿；英文段落以此为准。

## 摘要（A1–A8）
- A1 已部署的冻结预测模型会收到含缺失观测的请求。
- A2 修复能否改善预测因请求而异，因此需要在候选修复与保留原输入之间选择。
- A3 提出 INTROACT-TS：冻结预测器下的请求级修复选择。
- A4 历史全动作回放提供相对 KEEP 的预测效用监督。
- A5 线上按动作检索邻近记录，以离散度惩罚的分数决定执行或 KEEP。
- A6 评估覆盖八来源、三骨干、四种缺失模式、两个预测长度（post-hoc）。
- A7 主要结果：对 KEEP 的误差优势广谱成立，干预损害低于固定修复。
- A8 对较强简单对照的优势集中、独立评估仍必要。

## §1 引言（6 段）
- I1 部署场景：冻结预测器收到不完整请求，本文限定有效观测不可改写，问题是修复与否要按对预测的影响判断。
- I2 已有工作分别在重建、训练预测器、任务导向评价和域级适配环节处理缺失，本文沿用下游评价并研究固定目录中的请求级选择。
- I3 修复效用相对 KEEP 定义、随请求与骨干变化，部署时未来目标不可见；历史窗口目标已观测，可成对比较得到效用标签；剩下的是如何用标签估计新请求的效用。
- I4 INTROACT-TS 离线存效用标签与检索状态，在线按动作检索局部均值与离散度，惩罚后取正分最高动作、否则返回缓存的 KEEP 预测；每请求一次参考预测加至多一次骨干调用，候选构造另计。
- I5 贡献：形式化请求级修复选择（含 KEEP）、历史效用驱动的选择程序、覆盖八来源三骨干并保留强简单对照的系统评价。
- I6（并入 I5 或独立短段）评估性质：此前测试结果参与过开发，结果为探索性，独立确认仍必要。

## §2 相关工作（3 小节）
- R21 已有研究在重建缺失值与训练预测器两个环节处理缺失，任务导向方法把评价延伸到下游；本文候选来自修复模型，决策层决定是否使用。
- R22 TATO 证明历史任务表现可选择数据侧变换，但其适配单位是目标域；本文按请求决策；TS-ICL 在本文仅作为两个候选动作的修复后端。
- R23 选择性预测以覆盖率换风险、learning to defer 转交请求，而本文对每请求保留同一预测器、只选择是否修改输入；历史全动作回放提供完整动作反馈，区别于部分动作日志。

## §3 方法（5 小节）
- 3.1
  - M11 定义请求、掩码、目标与冻结流水线 F（骨干内部预处理细节移至附录 B）。
  - M12 定义动作目录、KEEP 与相对 KEEP 的预测效用，决策目标是在看不到 Y 时选动作。
  - M13 四条部署约束：不改写有效观测、修复值域、未来目标不可见、决策前只算参考预测。
- 3.2
  - M21 历史窗口目标已观测，注入同一缺失协议、执行全部动作、与 KEEP 成对比较得到效用标签。
  - M22 每个标签与检索状态一起保存，状态用于把历史记录匹配到部署请求，回放库按骨干建一次并冻结。
  - M23 回放库按骨干版本与登记的缺失协议界定适用范围。
  - M24 局部估计假设邻近状态效用相近（该假设的检验见 §4.5 与附录）。
- 3.3
  - M31 状态含四组信息；现目录下五个干预坐标中四个恒零（附录 B），估计在标准化空间按动作分别检索。
  - M32 邻域、权重（带宽取自邻域中位数）、局部均值/离散度/有效样本数的定义与各自作用。
- 3.4
  - M41 局部均值相同而离散度不同，故从均值减惩罚得到分数，正分最高才执行、否则 KEEP；分数是经验规则，无校准保证。
  - M42 k 与 β 在回放库上以 leave-one-parent-out 交叉验证选取，受有害率上限约束；如实描述不可行分支的记录行为；选定的锚点、上限与参数对运行冻结。
  - M43 规则总返回预测，且无支持范围外检测，结论限于登记网格内。
- 3.5
  - M51 在线两阶段：参考预测+候选构造与状态，再检索评分、执行选中动作或返回缓存参考预测。
  - M52 成本：一次参考骨干调用加至多一次选中动作调用；候选构造（含其他模型调用）在选择前支付，与骨干调用分列统计。

## §4 实验（7 小节）
- 4.1 Evaluation Protocol
  - E11 评估对象：八来源、三骨干、各自回放库、L=512、H∈{96,192}、主缺失率 10%。
  - E12 对照及其各自检验的问题：KEEP（是否需要外部修复）、固定修复（是否需要请求级选择）、R2-CART（复杂设计的增量）、SAITS 与 TATO。
  - E13 划分、净化、聚合与统计单位（parent 聚类 bootstrap）。
  - E14 证据性质：TEST 曾参与开发，所有比较为 post-hoc，不构成独立确认。
- 4.2 Variation in Repair Utility
  - E21 没有单一动作对所有请求最优，oracle 显示存在选择空间——只支持"潜在收益存在"。
  - E22 同一请求内重建排序与预测效用排序经常不一致，故直接以预测效用监督。
  - E23 桥接：潜在收益不等于可实现，4.3 检验可部署规则。
- 4.3 Forecasting Performance
  - E31 总体结果：1.437 vs KEEP 1.576 / BF 1.488 / R2-CART 1.458 / SAITS 1.459 / TATO 1.616；骨干间有差异（TimesFM 上 SAITS 最低）。
  - E32 配对区间：对 KEEP 三骨干全显著；对 BF 与 R2-CART 区间含零。
  - E33 秩次最低但仅为描述性；随后来源固定策略：两骨干上显著优于 FULL，集合接近。
  - E34 留一来源：对 KEEP/TATO 的优势广谱，对 BF/R2 的优势集中于 Exchange。
  - E35 桥接：平均误差不区分收益与损害，需检查干预频率与损害。
- 4.4 Intervention Frequency and Harm
  - E41 默认工作点：干预率 65.4%、条件有害率 40.2%、有害损失 0.0375，低于 BF 与 R2-CART。
  - E42 机制问题：较低损害可能只来自较少干预，需对照区分；随机门控保留同一推荐动作只随机是否执行，与阈值/固定动作+随机 KEEP 是三类不同对照。
  - E43 结果：对随机门控三骨干误差显著更低但有害损失更高；对 mean-only/linear 只在单骨干显著；频率匹配伙伴：对 BF-Random 全显著、对 R2-CART-M 仅 Bolt 显著；两类对照实际 TEST 频率低于开发目标，非严格同预算。
  - E44 小结落在准确率-损害权衡，不写安全保证。
- 4.5 Effects of Utility Estimation and State Representation
  - E51 效用估计：全局均值（A1）→分动作 pooling（A2-M）→线性预测（A5），各改变什么机制、结果与适用范围；pooling 不是完美单因素消融。
  - E52 状态信息：reference-forecast 特征（A3）与固定配置下删除干预特征（A2-F，1.4185）；四个恒零坐标的实现事实影响消融含义。
  - E53 表示选择 vs 固定配置消融：重新选参的 Compact 是表示+参数共同变化的另一种比较；DEV 证据混合（TimesFM 显著退化、Chronos-2 改善、两者有害损失升），按开发侧采用规则保留 Full；细节在附录 E。
- 4.6 Sensitivity to Missingness and Replay Support
  - E61 缺失严重度：30%/50% 不重调参，对 KEEP 优势保持但 R2-CART 在高严重度反超；三个严重度都在回放网格内，属协议内分析。
  - E62 历史支持：bank 大小、选参稳定性、掩码实现变化分别改变历史支持、所选参数与缺失实现，均非独立泛化验证（详见附录 F）。
- 4.7 Deployment Cost
  - E71 按 §3.5 顺序报告计算组成：骨干调用实测 1.65 次/请求；候选构造、检索、冷启动分列；端到端延迟未实测不报分位数；结论只回答"请求级选择增加了哪些计算"。

## §5 结论（4 句）
- C1a 回到研究问题：冻结预测器下的请求级修复选择。
- C1b 方法概括：历史全动作回放提供效用监督，局部估计加离散度惩罚形成 ACT-or-KEEP 决策。
- C1c 已核实发现：对 KEEP 的改善广谱成立，对较强简单对照的优势受骨干与来源限制，干预呈现准确率-损害权衡。
- C1d 证据边界：开发使用过 TEST，独立数据确认与自然缺失场景仍待检验。
